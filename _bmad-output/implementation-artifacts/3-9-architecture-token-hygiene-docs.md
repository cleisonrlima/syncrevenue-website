## Story

so that I stop rediscovering conventions via grep and we have an enforceable token-contrast baseline — closing Epic 2 retro action items A3 and A5.

This story implements the `❌ Not addressed — Carry forward` rows A3 (Reusable patterns gallery doc) and A5 (Brand-token WCAG AA validation at token level) in `_bmad-output/implementation-artifacts/epic-2-retro-2026-05-15.md`.

## Acceptance Criteria

1. **Given** the project's canonical patterns are currently scattered across `vault/Planning/Architecture-Key.md`, individual story files, and code, **when** a patterns gallery is authored, **then** a new vault note `vault/Code/Patterns-Gallery.md` is added that catalogs each canonical pattern (Lazy + Suspense + ErrorBoundary trio, DAO factory + default singleton, `createApp()` test harness, `void sendNotification(...).catch(...)` fire-and-forget SMTP, API-envelope `success: true` strictness, `useImperativeHandle` multi-CTA convergence, `defaultValue` discipline on every `t()` call, `forwardRef` form components, co-located tests, i18n key max-depth (3 levels), locale-from-store (`useLocaleStore`, not `i18next.language`), `data-*` markers for test selectors); each entry includes: pattern name, where to use it, one-line code snippet, file path with line range, and at least one rejected alternative.

2. **Given** brand tokens are defined in `tailwind.config.ts` via CSS custom properties in `src/index.css` (`--color-electric-blue #0075F0`, `--color-highlight #00A0F0`, `--color-deep #0055F0`, `--color-navy #0D0D3A`, `--color-slate #404070`, `--color-muted #8080A0`, `--color-offwhite #F4F6FA`), **when** a contrast manifest is generated, **then** a new file `src/lib/brand-tokens.contrast.manifest.ts` exports a typed table (`BrandContrastEntry[]`) of every brand foreground token plus `#FFFFFF` against the production text-bearing surfaces (`white`, `offwhite`, `navy`) with: `fg` (token name), `bg` (token name), `fgHex`, `bgHex`, `ratio` (number, 2 decimals), `aaNormal` (boolean — pass if `ratio >= 4.5`), `aaLarge` (boolean — pass if `ratio >= 3.0`), and `waiver` (`null | { id: string; reason: string }`); the manifest is regenerated by a new script `scripts/check-brand-contrast.mjs` (Node ESM, no extra deps — pure JS contrast math, same algorithm as the existing test) that writes the file deterministically, and the script is wired to `npm run check:contrast` in `package.json`.

3. **Given** the existing `src/lib/brand-tokens.contrast.test.ts`, **when** it is extended, **then** it imports the new manifest and asserts: (a) no entry has `aaNormal: false` AND `waiver === null` (a new failing pair without an explicit waiver fails the test); (b) the R-A2 electric-blue-on-white entry is present with `aaNormal: false`, `aaLarge: true`, and `waiver.id === 'R-A2'`; (c) every entry's computed `ratio` matches the test's own `contrastRatio(fgHex, bgHex)` within 0.05 (manifest stays in sync with the math); the existing positive-path assertions (`brand-deep on white`, `brand-deep on offwhite`, `offwhite on navy`, `white on navy`) continue to pass; total test count for this file increases, not decreases.

4. **Given** the patterns gallery, **when** linked from existing surfaces, **then** `vault/00-Home.md` (Quick Navigation table), `vault/Planning/Architecture-Key.md` (new top-of-document link in the canonical-patterns section, replacing or augmenting the inline list), and `vault/Code/Index.md` (Modules section, new "Patterns" row) all link to the new gallery via `[[Code/Patterns-Gallery]]` Obsidian-style links; the gallery itself documents at least three anti-pattern counter-examples (e.g., `__tests__/` directories, hand-rolled `fetch()` wrappers bypassing `src/lib/api.ts`, hardcoded English copy in user-facing UI bypassing `t(..., { defaultValue })`).

5. **Given** the changes, **when** committed, **then** Epic 2 retro rows A3 and A5 in `_bmad-output/implementation-artifacts/epic-2-retro-2026-05-15.md` (lines 107 and 109) flip from `❌ Not addressed` to `✅ Done` with the Story 3.9 commit hash in the Evidence column; the corresponding §7 action-plan rows B4 (line 173) and B7 (line 176) are annotated `[done in Story 3.9: <commit>]`; `npm run typecheck && npm run test:run && npm run build` all pass; `npm run check:contrast` runs successfully and the manifest is committed in its generated form (running the script must be a no-op on a clean tree — diff-free).

## Dev Notes

### Relevant architecture patterns and constraints

- **Vault layout:** notes use Obsidian wiki-style links `[[Code/Patterns-Gallery]]`. Do not use Markdown-relative links like `[Gallery](./Patterns-Gallery.md)` — breaks the project's Obsidian convention.
- **Canonical patterns list source:** the 12 patterns enumerated in AC1 come from epic 1 retro § "Canonical Frontend Patterns" + epic 2 retro § "Patterns honored / proven this epic". Cross-check against `vault/Planning/Architecture-Key.md:139-176` and `_bmad-output/implementation-artifacts/epic-2-retro-2026-05-15.md` § 3 before authoring. If a pattern's file:line is stale, re-locate via grep at write time — the gallery is reference material and must be accurate on `master`.
- **Contrast math:** keep the algorithm identical to `src/lib/brand-tokens.contrast.test.ts:25-46`. The existing R-A2 assertion (`toBeCloseTo(4.37, 1)`) is the canonical reading; any deviation in the manifest's ratio for that pair is a math bug.
- **R-A2 waiver:** must remain honored. The existing `Architecture-Key.md:124-133` documents it; the manifest is the new enforcement surface, but the waiver text itself stays in Architecture-Key (single source of truth for the policy).
- **No new deps:** `wcag-contrast`, `color`, `chroma-js`, etc. are all unnecessary — the pure-JS math is ~20 lines.
- **TypeScript strictness:** `tsconfig.json` is `strict: true` (Story 1.1). Manifest types must be exact: no `any`, no `as unknown as`. The `waiver` field is `{ id: string; reason: string } | null` — narrow with `if (e.waiver) { ... }` at test sites.
- **Generated-file convention:** the manifest header banner mirrors the pattern used by `dist/client/sitemap.xml` generation (see `scripts/generate-seo-assets.mjs`). Keep ISO-date stamp at second-precision to keep diffs minimal across reruns within the same day (use `new Date().toISOString().slice(0, 10)` — day precision).
- **Script style:** match `scripts/check-client-bundle-secrets.mjs` and `scripts/generate-seo-assets.mjs` — Node ESM (`.mjs`), no Babel, top-level `process.exit` on failure, explicit `console.log` for the generation summary line.
- **Idempotency:** Task 4's "second run is diff-free" check catches `Date.now()`-flavored leakage early. If the script writes the date, it's day-precision (above) — running twice on the same day must produce identical files.
