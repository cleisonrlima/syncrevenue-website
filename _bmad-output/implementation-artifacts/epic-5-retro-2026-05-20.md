## 3. What Went Well

### 3.1 Cross-Story Infrastructure Cohesion

The six Epic 5 stories built cleanly on each other without rework loops. Story 5.1's `ecosystem.config.js` was extended once (review: `max_restarts`, log paths) and never revisited. Story 5.2's HSTS/CORS/redirect middleware coexisted with Story 5.3's `validateEnv()` guard without conflicts. Story 5.5's health route extracted cleanly from the inline `app.get('/api/health', ...)` stub that had been present since Epic 2 — a planned refactor that landed without friction.

### 3.2 Security Review Caught a Real Vulnerability

Story 5.3's cross-model review caught a non-trivial JWT_SECRET whitespace bypass: a value of `"abc" + " ".repeat(29)` (32 chars raw, 3 chars of real entropy) would have passed the `validateEnv()` length check and reached `jsonwebtoken` as a weak signing key. The `.trim()` fix was one line, but the consequence of missing it in production would have been a cryptographically weak JWT signing key. This is the kind of finding that justifies adversarial cross-model review as a hard project rule.

### 3.3 SSG Prerender Delivered the LCP Target Without Third-Party Dependencies

Story 5.6 achieved LCP 2,259 ms median (target: < 2,500 ms) by implementing a custom `scripts/prerender.tsx` using `tsx` (already a devDependency) and React's `renderToString` + `StaticRouter`. Both `vite-plugin-ssg` (unmaintained for React 18) and `react-snap` (300 MB Chromium dep) were evaluated and rejected on principled grounds. The chosen approach added zero runtime dependencies and zero client bundle weight while reducing mobile LCP by 83% from the baseline. The `hydrateRoot` fallback detection in `src/main.tsx` was clean and future-proof.

### 3.4 Documentation Artifacts Are Production-Grade

Three documentation files were created:

- `docs/deployment-runbook.md` — SSL/TLS (Certbot + Nginx, Caddy auto-TLS), HTTP→HTTPS at proxy and application level, env-var checklist, DB persistence guidance, first-deploy checklist, zero-downtime PM2 reload. Amended post-review with the HSTS preload irreversibility caveat.
- `docs/backup-cron-setup.md` — cron line, manual verification, PM2 isolation note.
- `docs/monitoring-setup.md` — UptimeRobot free-tier setup, keyword monitoring on `"status":"ok"`, PM2 crash/recovery notes, autocannon p95 verification guide.

Unlike Epic 2's doc debt (architecture.md drift that wasn't caught until Epic 3), Epic 5's docs were written as part of the story AC and reviewed at the same time as the code. No post-hoc reconciliation needed.

### 3.5 Backup Script Review Found the `set -euo pipefail` + `find -delete` False-Positive

Story 5.4's backup script used `set -euo pipefail` which caused `find -delete` to abort the script on permission errors for stale backup files owned by a different user. The review caught this and applied `|| true` on the `find` line. Without this fix, every backup run on a mixed-ownership backup directory would have reported failure even though the backup itself succeeded — poisoning cron monitoring and potentially masking the real failure signal.

### 3.6 Adversarial Review Maintained Quality Throughout

Every story received a cross-model review, and every review found at least one actionable item:

- 5.1: PM2 crash-loop guard, HTTP/1.0 Pragma/Expires headers, log path configuration, `.gitignore` logs/
- 5.2: HSTS preload caveat documentation, CORS test `try/finally` cleanup, trust proxy deferred to 5.9
- 5.3: JWT_SECRET whitespace bypass (security), `.trim()` fix + 1 new test
- 5.4: `set -euo pipefail` + `find -delete` false positive
- 5.5: `vi.doUnmock` not in `try/finally` — mock could leak across tests
- 5.6: `npx tsx` → `node_modules/.bin/tsx` (version pinning), prerender type coverage deferred to 5.8

## 4. What Could Be Better

### 4.1 Recurring Issues (2+ Stories)

**Issue 1: Review always found test cleanup gaps.**

Stories 5.2, 5.4, and 5.5 all had test code that could leak state across tests due to missing `try/finally` cleanup:

- 5.2: CORS test restored `ALLOWED_ORIGIN` and reset modules outside `try/finally`
- 5.4: Backup test cleanup patterns were solid, but `find -delete` false positive in the script itself
- 5.5: `vi.doUnmock` not in `try/finally` — mock registration would persist if assertion failed

Pattern: developers consistently forget to apply `try/finally` cleanup in test teardown. This is a known class of test debt. It never caused a test failure in Epic 5 (CI always runs tests in isolation), but in full-suite runs it creates hard-to-diagnose flakiness.

**Actionable:** Add test cleanup discipline to the PR review checklist. Any test that calls `vi.doMock`, `vi.resetModules`, or mutates `process.env` must use `try/finally` for restore.

**Issue 2: Story 5.2 status was `ready-for-dev` and tasks were `[ ]` at review time despite implementation being complete.**

The dev agent committed all code (commit `67b3fea`) but forgot to update the story file status from `ready-for-dev` to `done` and check the task boxes. This is an R1 CRITICAL finding in the review — critical not because of code quality but because an incorrect status would mislead sprint tracking and Jira sync.

Pattern: story file updates are a separate step from code implementation. The dev agent record shows implementation was complete, but the housekeeping step was skipped. Story 5.1 had the same finding (story file not updated before review).

**Actionable:** Story automator dev step must include an explicit final task: "Update story file status → `done`, check all task boxes, add Dev Agent Record." This should be a required last task in every story, not an afterthought.

**Issue 3: `npx` used instead of the pinned binary (`node_modules/.bin/tsx`).**

Story 5.6 initially wired the build extension as `npx tsx ...` instead of `node_modules/.bin/tsx ...`. This introduces a `npx` registry-check round-trip on every build and risks version drift if the npm cache is cold. Found in review and patched.

Pattern: `npx` is a convenience tool for ad-hoc runs, not for committed build scripts. Committed scripts should always reference the pinned binary directly. This was also flagged in earlier epics (Epic 2 had similar `npx vitest` → direct binary issues).

**Actionable:** Add to story spec template: "If wiring a new npm script, use `node_modules/.bin/<tool>` not `npx <tool>`."

### 4.2 Process Gaps

**Gap 1: CI coverage gap for `scripts/backup.test.mjs` (TEA finding G1, score 9)**

The backup test suite is solid (3 integration tests covering happy path, retention, and error exit). But `npm run test:backup` is not in `.github/workflows/quality.yml`. The CI pipeline runs Vitest and Playwright but never the backup tests. This means a regressed `backup.sh` or `backup.test.mjs` would not block a PR merge.

TEA scored this G1 (9/9 — mandatory gate failure). Story 5.10 is queued to fix this.

Root cause: the backup script was implemented as a standalone Node.js harness (`backup.test.mjs`, not Vitest), which is the correct architecture (no Vitest dependency for a bash script test). But adding it to CI was not part of Story 5.4's AC and was overlooked.

**Gap 2: `scripts/prerender.tsx` excluded from TypeScript typecheck**

The prerender script is excluded from `tsconfig.json`'s `include` array because it targets Node.js module resolution while the main tsconfig targets Vite/browser module resolution. As a result, `npm run typecheck` (run in CI) silently skips it. Type regressions in the prerender step are invisible to CI — only the LHCI job (which runs `npm run build`) catches them, and LHCI is not in the critical CI path.

Story 5.8 is queued to add a dedicated `tsconfig.scripts.json` and extend the typecheck script.

**Gap 3: Trust proxy not configured**

`app.set('trust proxy', 1)` was identified in Story 5.2's review as missing. Without it, `req.protocol`, `req.secure`, and `req.ip` return incorrect values behind a TLS-terminating reverse proxy. The HTTP→HTTPS redirect middleware reads `X-Forwarded-Proto` directly (bypassing the trust proxy issue), but rate limiters that use `req.ip` for per-IP windows are potentially affected.

Story 5.9 is queued.

**Gap 4: Health DAO has no dedicated unit tests (TEA finding G2)**

`server/dao/health.dao.ts` is the only DAO in `server/dao/` without a dedicated `*.dao.test.ts` file. The route tests provide indirect coverage, but the DAO factory and `ping()` failure path are not tested in isolation. Story 5.11 is queued.

### 4.3 Technical Debt Accumulated

**High priority (queued for next sprint as Stories 5.7–5.11):**

- **5.7 — PM2 Cluster Mode**: `ecosystem.config.js` uses `instances: 1` by default. Cluster mode requires WAL mode analysis for SQLite concurrent writes and an ADR. Non-trivial architecture decision.
- **5.8 — Prerender Script Type Coverage**: `scripts/prerender.tsx` not in typecheck scope. Needs `tsconfig.scripts.json` with Node.js module resolution.
- **5.9 — Express Trust Proxy Configuration**: `app.set('trust proxy', 1)` missing. Affects `req.protocol`, `req.secure`, `req.ip`.
- **5.10 — CI Quality Gate**: `npm run test:backup` not in CI; no build-output smoke test for prerender HTML after `npm run build`.
- **5.11 — Health DAO Unit Tests**: `server/dao/health.dao.ts` needs `health.dao.test.ts` with ping() happy path, closed DB throws, factory pattern.

**Medium / low (carry-forward):**

## 8. Key Takeaways

1. **Adversarial cross-model review caught the only real security finding of the epic** (JWT_SECRET whitespace bypass in Story 5.3). The finding was non-trivial — a subtle entropy-weakness that would have passed all other checks. Cross-model review is non-negotiable on security-adjacent stories.

2. **Infrastructure documentation written during AC is higher quality than documentation written after the fact.** Epic 5's three runbooks were accurate on first review and required only one amendment (HSTS preload caveat). By contrast, Epic 2's architecture doc drifted for an entire epic before reconciliation.

3. **TEA's CI gap finding (G1, score 9) was correctly prioritized.** `npm run test:backup` not in CI is the single highest-risk finding of the epic — not because the backup tests are wrong but because CI is the enforcement mechanism. A quality gate without coverage of build-adjacent scripts is a blind spot. Story 5.10 addresses this.

4. **Custom prerender is superior to third-party SSG plugins when ecosystem maturity is uncertain.** `vite-plugin-ssg` was unmaintained for React 18; `react-snap` required a 300 MB Chromium dep. The custom `tsx`-based approach was ~80 lines, zero new runtime dependencies, and delivered LCP 2,259 ms — better than the 2,500 ms target.

5. **Test isolation failures are systemic, not random.** Stories 5.2, 5.5, and to a lesser extent 5.4 all had test teardown gaps caught in review. This is a class of defect, not individual carelessness. The `try/finally` discipline rule (Action C1) is the systemic fix.

6. **The "story file housekeeping" step is consistently skipped.** Two stories (5.1 and 5.2) had review findings that the story file status was still `ready-for-dev` post-implementation. Making "update story file" an explicit final task (Action C2) closes this gap at the process level.
