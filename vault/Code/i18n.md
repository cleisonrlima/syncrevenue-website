## Locale Change Flow (always this order — enforced by arch spec)

```typescript
i18next.changeLanguage(locale)          // 1. update i18next (triggers re-renders)
useLocaleStore.setState({ locale })      // 2. update Zustand store
localStorage.setItem('i18nextLng', locale) // 3. explicit persist
```

---

## Rules

- Source locale in components from `useLocaleStore` — never directly from `i18next.language`
- `import './i18n'` must be the FIRST import in `main.tsx` before React
- `main.tsx` syncs Zustand store to i18next-detected locale at startup
- `useSuspense: false` — resources are bundled, not async-fetched
- All validation errors locale-aware (FR16, FR20)
- Only `en`, `pt-BR`, `es` allowlisted server-side (FR40, Story 2.7)
