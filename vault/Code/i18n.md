# i18n Module

**Stack:** i18next + react-i18next + i18next-browser-languagedetector

---

## Supported Locales

| Code | Language | Primary Market |
|---|---|---|
| `en` | English | US / Canada (default) |
| `pt-BR` | Brazilian Portuguese | Brazil |
| `es` | Spanish | Latin America |

---

## Files

| File | Description |
|---|---|
| `src/i18n/index.ts` | i18next init, detector config |
| `src/i18n/en/translation.json` | English strings |
| `src/i18n/pt-BR/translation.json` | Portuguese strings |
| `src/i18n/es/translation.json` | Spanish strings |

---

## Detection Order

```
localStorage ('i18nextLng') → browser preference → fallback: 'en'
```

---

## Key Structure (dot-nested, max 3 levels)

```json
{
  "nav": { "demo": "...", "contact": "..." },
  "hero": { "headline": "...", "cta": "..." },
  "forms": {
    "demo": { "name": "...", "emailError": "...", "submit": "..." },
    "contact": { "subject": "...", "submit": "..." }
  },
  "admin": { "leads": { "title": "..." } },
  "privacy": { "title": "..." }
}
```

---

## Locale Change Flow (always this order)

```typescript
i18next.changeLanguage(locale)
useLocaleStore.setState({ locale })
localStorage.setItem('i18nextLng', locale)
```

---

## Rules

- Source locale in components from `useLocaleStore` — never directly from `i18next`
- All validation errors locale-aware (FR16, FR20)
- Locale captured in every form payload before submission
- Only `en`, `pt-BR`, `es` allowlisted server-side (FR40)
